# 完整课程反复失败的全局复盘

日期：2026-10-16。对象：DGX Spark 课程容器、Isaac 6.0 恢复副本与 Jazzy Nav2 1.3.13。实施进度只在 `MIGRATION_TODO.md` 更新。

## 结论

失败发生在不同层，不能归为一个参数问题。本轮先验证了**底盘运动模型不一致**，候选轮径已经显著改善实测增益；随后暴露了**运动中的定位分歧**，这是下一步应先处理的阻塞。完整课程另有**安全站位、抓取姿态、物体位置未联合设计**的问题。继续反复发送六米长的同一个导航目标，无法有效区分这些问题。

### 1. 底盘控制元数据与接触几何不一致：优先级最高

- 三个驱动关节的 `isaacmecanumwheel:radius` 都是 0.035 m。
- 实际接触滚轮是位于独立兄弟组件中的球碰撞体，不能用空的 `*_wheel_link` 包围盒判断。每轮10个球，球半径约0.033 m，球心距轴约0.011 m，径向外缘约0.044 m。
- 0.044/0.035≈1.257，与真实普通制动试验中命令0.04 m/s、真值峰值0.051153 m/s相近。已有运行还显示角/侧向扰动。
- 这是直接模型证据和相符的运行证据，**尚不是有效滚动半径标定**：离散球接触、滑移、驱动阻尼和时延仍可能影响结果。不能只改一个数字就宣称解决。
- 证据：`reports/world-global-wheel-geometry.json`、探针及日志，`world-bounded-normal-brake.json`。后者实际运行的恢复USD哈希为9383aec5…；本次不改原始USD、机器人资产及dirty course。

### 2. 低加速度MPPI、后级平滑器和仿真时序组合不匹配：高可能

- 最新失败运行 `/cmd_vel_nav` 中位周期约0.0333 s仿真时间，而配置预测步长0.05 s；其墙钟周期约0.05 s，实测RTF约0.59。后级仿真时钟平滑器中位周期0.05 s。`use_sim_time=true`没有把上游墙钟循环变为仿真时间循环。
- 安装的1.3.13头文件仍会在预测中修改采样控制；同版本上游优化器没有新的首控制量与测量速度之间的可行性约束。不能因二进制构建日期较新就认为包含main分支修复。
- Nav2作者已专项分析低加速度下的预测/执行不一致、控制序列首点、时序和采样噪声，提供了main分支修复。其实现与本项目Jazzy不是同一套；禁止直接混装main覆盖Jazzy依赖。
- 这些因素可能解释启动方向偏差、抖动及后级不断修正；**还没有证明是此次取消的唯一根因**。之前独立自由地图MPPI回放只说明偏差可在简化模型中出现，不是物理证据。

### 3. 路径与控制器、验收任务的选择：中等可能

- 栅格起点连接可能先向西南，再折向西北；持续重规划还会改变局部初段。ConnectedSmac解决了起点缺失，没有保证首段平滑。
- MPPI优化多项代价，不能从PathAlign权重大就推出全程误差≤0.05 m。20→80的一次随机回放改善有限，不能成为新的主线。
- 最新真正停止原因是预测跟踪保护：误差0.0270 m且继续向外增长。包含制动最大误差0.0309 m、净距下界1.2795 m；这是保护有效，不是目标成功。
- 不通过放松0.55 m净距/0.05 m偏差来获得“成功”。先以短直线、短斜线和单拐角证明跟踪，再执行长路线。
- 本轮新增真实短目标进一步量化：MPPI路径初段向目标反方向折返约49 mm，终点偏离请求约58.5 mm；RPP对应约21.6/49.6 mm。所谓“0.3 m直线目标”并不产生直线路径。MPPI发生进度失败后由A取消；RPP在预测跟踪门禁取消、最大偏差24.8 mm。两次输入并非完全相同，不能据此作控制器优劣结论。证据 `world-global-short-grid-confounds.json`。

### 3a. 动态定位与真值分歧：已追到AMCL修正层

恢复计划实测把误差分层了。七次有界脉冲合并后，5684条原生odom只用首帧建立一次world对齐；2052个源时间比较点的原生位置误差最大0.357mm，map位置误差最大12.062mm，速度推算的真值时间区间不确定度最大0.343mm。完整倒装雷达旋转已用于扫描投影。这些短脉冲通过，不代表更长运动中的AMCL修正通过。

后续MPPI固定0.3m直线复现定位失败：原生odom最大0.183mm、TF odom对原生odom最大0.085mm，但AMCL在1181.0667s发布的位姿与同时段真值差37.143mm。该修正约5秒后进入按源时间查询的map→odom，触发30mm门禁。实际跟踪最大11.332mm，轨迹净距下界0.994150m；已取消、停稳。录包及重算见 `world-recovery-fixed-mppi-{bag,decoded.json,analysis.json}`。这次失败首先发生在AMCL修正，不能归因于原生odom漂移。

对应安装版本的[官方OmniMotionModel](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_amcl/src/motion_model/omni_motion_model.cpp)根据运动量与alpha1–5生成粒子运动噪声；当前五项均为0.2，失败更新的XY标准差约0.134/0.147m，和实测近乎精确的仿真odom不匹配。只在独立运行副本将同组系数降至0.001，保持5秒TF容差、更新阈值和地图。第一次候选因TF墙钟等待过短中止；修复观察器后再试，真实AMCL重采样已发生，源时间位置误差最大0.220mm，但MPPI预测跟踪保护在41.159mm触发，含制动最大47.104mm。候选是局部定位改进证据，仍不是导航成功；起始状态和路径长度不同，不称严格配对的完整因果证明。

同时发现观察器的独立问题：实际TF发布间隔出现0.657秒墙钟、仅0.1秒仿真推进，原固定0.5秒墙钟等待会提前失败。公共工具改为保持原采样时间戳，同时限制0.15秒仿真新鲜度与1.5秒墙钟看门狗；暂停、回退、非有限值均拒绝，未替换成latest TF。容器10项公共保护回归先红后绿；原失败报告保留。下一步按原计划执行RPP对照，不继续堆叠MPPI权重。

以下为本次分层诊断前的历史证据，保留其当时的未知项：

- 去掉全局栅格与重规划后，RPP执行一次经过整段净距门禁的人工固定直线FollowPath，仍因定位误差超过0.03 m取消。过程中确实前进约0.19 m；该试验不是全局导航通过。
- 启动时定位位置误差已约0.0268 m；包含取消后记录的峰值约0.0449 m，真实轨迹最大偏差约0.0270 m。它说明“静止初始对齐通过”不能替代运动中的定位验证，也限制了当前控制器比较的有效性。
- 当时原因未确定，因此要求分别检查原生odom、TF、采样时间和完整雷达旋转，再决定是否修改参数。
- SDK真值服务没有源时间戳，记录使用请求/接收仿真区间；该历史试验本身缺少odom pose和TF源时间，不能单独证明AMCL根因。证据 `world-global-fixed-{plan,motion}.json`；新的分层结论依据本节上面的独立录包。

### 4. 导航站位与抓取条件没有联合验证：完整课程的独立阻塞

- `(2.35,0.6,π)`是导航暂驻目标，不是已验证抓取位姿。实际物体x=1.4；既有真实MoveIt检查在该站位未找到指定垂直抓取的无碰撞IK。这不等于数学上证明所有姿态都不可达。
- 假想物体x=1.65时，站位x=2.15/2.10有含桌子碰撞体的完整下降及5 cm提升规划，但到桌板x=1.7外缘的中心距离只有0.45/0.40 m，低于现有0.55 m门槛，不能直接执行。
- 因此，已有“导航可行”和“抓取可行”证据对应不同条件，尚无交集。需联合搜索物体支撑、站位净距、机械臂完整轨迹和相机可见性；必要时仅在独立课程副本调整教学布局。不可将未支撑的桌边物体或放松保护作为捷径。
- 正向视觉识别、带反馈夹持和物体随夹爪提升仍未通过；应在固定底盘位置先验证，避免全部失败都表现为“完整流程失败”。
- 源码另有成功判据缺口：`grasp_control/gripper_control_node.py`发布一次目标后按时间等待即报告REACHED，未订阅夹爪位置；`grasp_state_machine.py::verify_position_reached()`在没有关节数据时仍返回True。这些尚未触发本次导航取消，却使后续Action成功不能代表真实抓取成功。应补反馈、取消与超时，并以物体实际离桌验证。

### 5. 场景来源漂移与验证顺序放大了调试成本

- 原dirty course与地图记录不匹配，CTest仍有一组失败；恢复副本另有相符的13个静态碰撞体审计。原dirty文件保留，不能掩盖来源测试失败。
- 早期反馈放大/零请求不停止是已复现并修复的缺陷；当前最新目标没有该失控或PhysX非有限故障。它们是历史失败原因，不能解释所有后续失败。
- 原有做法过早把定位、随机控制、重规划、执行器、保护与长目标同时放进一次试验，失败信息混在一起。新的试验每次只检验一个假设，使用唯一输入/报告前缀和固定场景。

## 已有证据使哪些原因优先级降低

GPU/ARM64/容器挂载、真实传感器QoS及初始TF、当前world地图静态几何均有实际通过证据。上一轮长目标停止时定位误差约0.061 mm，之后只读检查机器人周围0.5 m代价图均为空闲。这使重新安装环境、再次调QoS的依据不足；本轮转向后新增的定位分歧另有证据，必须单独处理。

## 本轮对主要假设的实际验证

- 新增独立轮径副本，仅三个控制半径改为0.044 m。真实X向0.03 m/s基线稳态增益约1.223；候选正负X、正负Y约0.989–0.995，正负yaw约0.967/0.979。六方向均在10%筛选范围，强烈支持轮径模型不一致确实影响控制。基线与候选初始位置、朝向不同，不将它描述成完全相同初始条件下的唯一因果证明。
- 5/6次通过附加的严格停稳诊断。负yaw在0.005 rad/s判据下失败，后期角速度范围约[-0.0080,0.0142] rad/s，约4秒的yaw变化0.009 rad。失败保留。六次记录均满足课程已有StoppedGoalChecker的低速阈值（平移0.015 m/s、角0.02 rad/s）；后续按原配置评估，附加诊断不自动升级成新的课程验收要求。物理加速度上限仍未认证。
- 对安全站位2.30/2.35、原物体与桌内近边缘物体的指定垂直姿态，名义搜索仍未找到完整周期。改为保留物体长轴、倾斜30°/60°，假想物体x=1.65、站位(2.35,0.6,π)后，**真实MoveIt含六桌体碰撞的预接近规划、下降与5cm提升均通过**，零控制命令、临时碰撞体清理。它提供了共同候选，尚未移动物体、验证相机可见性或执行抓取。
- 优先课程候选因此收敛为：保留桌高、机器人结构、地图、暂驻站位与保护；在独立教学副本将物体置于桌内x=1.65，采用30°倾斜抓取。只有相机、碰撞与真实夹持后续通过，才采用为最终课程配置。
- 证据：`reports/world-global-radius-*.json`、`world-global-joint-{kinematic,tilt-staging}-screen.json`、`world-global-joint-tilt-moveit{,-input}.json`。运行结果只在TODO持续更新。
